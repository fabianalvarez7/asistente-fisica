Cómo incorporamos ejercicios al asistente

Propuesta de trabajo para revisar, cargar y publicar ejercicios de Física 1

Idea principal: el asistente no resolverá problemas de física arbitrarios. Solo trabajará con ejercicios que estén cargados, revisados y publicados en un catálogo controlado por el equipo.

1. ¿Qué problema resolvemos?

Los PDFs del curso contienen mucho material, pero no todo está listo para ser utilizado por el asistente. Un ejercicio puede necesitar una revisión del enunciado, del gráfico, de las unidades, de la respuesta esperada y de la forma pedagógica en que queremos acompañar al estudiante.

Por eso distinguimos entre el corpus académico (todos los materiales disponibles) y el catálogo de ejercicios habilitados (solo los ejercicios aprobados para estudiantes).

2. Proceso para incorporar un ejercicio

  1. Seleccionar: elegir un ejercicio concreto de una guía o PDF.
  2. Describir: registrar su fuente, página, enunciado, gráfico y conceptos involucrados.
  3. Revisar: verificar que el texto y los datos sean correctos y que el ejercicio esté bien delimitado.
  4. Preparar: definir qué debería poder acompañar el asistente y qué recursos visuales necesita.
  5. Validar: revisar ejemplos de respuestas y confirmar que respete el enfoque socrático.
  6. Publicar: recién entonces el ejercicio aparece disponible para estudiantes.

5. ¿Cómo interactúa el estudiante?

  1. El estudiante ve una lista de ejercicios publicados.
  2. Selecciona un ejercicio.
  3. El asistente muestra el enunciado y el material correspondiente.
  4. Las preguntas del estudiante se responden dentro del contexto de ese ejercicio.
Importante: ocultar ejercicios en la pantalla no es suficiente. El sistema también debe verificar internamente que cada consulta tenga un ejercicio válido y recuperar únicamente la información asociada a ese ejercicio.

6. Contrato de reintento al guardar una respuesta

El botón Confirmar respuesta envía un POST a /api/exercises/{exercise_id}/checkpoint. Antes de validar o avanzar el checkpoint, el servidor lee el progreso canónico del estudiante. Si esa lectura temporalmente no está disponible, responde con HTTP 503 y este cuerpo JSON: 

{
  "detail": {
    "code": "exercise_progress_unavailable",
    "message": "No se pudo leer tu progreso. No se generó una nueva guía. Reintentá.",
    "retryable": true
  }
}

retryable: true significa que la respuesta puede repetirse más adelante, pero que ese intento no avanzó el ejercicio ni debe generar una nueva guía. La interfaz muestra el mensaje, oculta temporalmente el checkpoint y desactiva el chat para evitar acciones sobre un estado que no pudo confirmarse. Al elegir Reintentar cargar el progreso, primero vuelve a consultar el progreso canónico mediante GET /api/exercises/{exercise_id}/progress. Solo si esa lectura tiene éxito vuelve a mostrar el checkpoint y permite enviar la respuesta nuevamente.

7. ¿Qué ocurre si pregunta por otro problema?

El asistente debe responder de forma clara y honesta:

“Todavía no tengo cargado ese ejercicio. Puedo ayudarte únicamente con el ejercicio seleccionado de Cinemática en 1D.”

Esto evita que el modelo improvise una solución basada en conocimientos generales o en un ejercicio que todavía no revisamos.

9. Criterio para sumar nuevos ejercicios

  • Agregar pocos ejercicios por vez.
  • Revisar cada uno antes de publicarlo.
  • Conservar la fuente original y la página de referencia.
  • Definir qué conceptos y resultados esperamos que el asistente pueda acompañar.
  • Probar preguntas correctas, preguntas ambiguas y preguntas fuera del ejercicio.
  • Publicar solo cuando la respuesta sea pedagógicamente aceptable.

10. Próximo paso

Comenzaremos con el ejercicio 2: prepararemos su ficha, aislaremos su material en la base de conocimiento, validaremos la interacción y recién después lo dejaremos visible en el asistente. El mismo procedimiento se repetirá para cada ejercicio nuevo.
